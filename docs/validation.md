# 검증 기록

검증일: 2026-10-24. Windows 사용자 데스크톱, Rust 1.98.1 환경에서 수행했습니다.

## 확인한 범위

| 항목 | 결과와 방법 |
| --- | --- |
| IME 판별 | 닫힌 IME의 이전 변환 플래그, 한글/영문 판별, 조회 실패에 대한 기존 테스트 통과 |
| CatchType 문구 | 결합 툴팁의 마지막 상태, 비활성 상태 우선 처리, 알 수 없는 문구에 대한 기존 테스트 통과 |
| 트레이 재시도 | Shell 실패 후 1초 제한, 최신 언어로 복구, 5초 등록 점검, 중복 재등록 테스트 통과 |
| 실제 Shell 등록 복구 | 앱 자신의 트레이 등록을 제거하고 TaskbarCreated를 전달한 뒤 타이머로 복구하는 네이티브 테스트 통과. 3회 반복과 중복 메시지, 종료 후 등록 제거 확인 |
| 배율과 경계 | 100/125/150/200% 크기·글꼴 배율 테스트 통과. 경계 보정은 300%까지 네 모서리, 음수 좌표, 작은 작업 영역에서 확인 |
| 실제 모니터 DPI | 현재 모니터 120 DPI(125%)에서 표시 크기 30px, 글꼴 DPI 일치, 작업 영역 안의 위치 확인 |
| 자원과 수명 | 오버레이 인스턴스별 상태 분리, 창 해제, 초기화 실패 시 불필요한 종료 메시지 방지, 잘못된 HWND 오류 처리 확인 |
| CatchType 실조회 | 180초 모니터 진단에서 CatchType 한글 상태와 Windows IME 영문 상태가 동시에 관측됨. 일시적인 모니터 결과 없음 이후 다시 한글 상태가 조회되는 경우도 관측 |

Shell 검증은 Explorer 자체를 종료하는 대신 **이 앱의 아이콘만 제거하고 재생성 알림을 전달**합니다. 다른 앱과 작업 표시줄을 중단하지 않고 복구 경로를 검증합니다.

CatchType 모니터 진단은 입력 내용과 창 제목을 기록하지 않습니다. 일시적인 모니터 결과 없음은 오래된 캐시를 버리거나 포커스가 바뀔 때 발생할 수 있으며, 이때 앱은 Windows IME를 사용합니다.

## 앱별 실사용 확인

2026-10-24 사용자가 메모장·VS Code·Chrome에서 물리 한영 키로 실제 입력과 커서 표시가 일치하며, 한글·영문 양방향 전환이 정상이라고 확인했습니다. 이는 사용자 확인 결과이며 자동 입력 테스트 결과와 구분합니다.

자동 조작으로는 새 빌드 실행, 메모장과 VS Code의 Caps Lock에 따른 `a → A → a` 표시, CatchType을 끌 때 Windows IME로 복귀하는 동작을 확인했습니다. Caps Lock은 끈 상태로 복구하고 CatchType은 다시 켰습니다.

자동화 도구는 전용 한영 키를 지원하지 않았고 Chrome의 현재 URL을 확실히 확인하지 못해 Chrome 조작을 중단했습니다. 이 도구 제한으로 남았던 실제 한영 전환 확인은 위 사용자 검증으로 보완했습니다. Chrome의 Caps Lock 표시와 주소창·입력창 사이 전환은 별도 확인이 남아 있습니다.

## 보류 및 추가 확인

배율이 다른 실물 모니터 사이 이동과 실제 Explorer 재시작 검증은 사용자 요청으로 이번 릴리스에서 보류합니다. 테스트 통과로 기록하지 않습니다. 배율·경계 계산 테스트, 현재 125% 모니터 검증, 앱 자신의 트레이 등록을 제거하고 복구하는 네이티브 테스트 결과는 그대로 유효합니다.

다음 항목은 구현·단위 테스트만으로 전체 호환성을 보장하지 못하므로 실제 사용 환경에서 추가 확인이 필요합니다.

| 대상 | 남은 확인 |
| --- | --- |
| Chrome | Caps Lock에 따른 a/A 표시, 입력창과 주소창 사이 포커스 전환 |
| CatchType | 자동 언어 전환, 일시 중지·로고 아이콘일 때 IME로 복귀 |
| 다중 모니터 (보류) | 서로 다른 배율의 실물 모니터 사이 이동, 연결·해제, 배율 변경 직후 표시와 글꼴 |
| 실제 Explorer 재시작 (보류) | 재시작 후 아이콘·종료 메뉴 복구 확인 |
| 권한이 높은 앱 / 원격 데스크톱 | IME 조회 권한과 입력 데스크톱 차이에 따른 동작 |

## 수동 확인 절차

1. 기존 HanEngCursor를 트레이 메뉴로 종료하고 새 빌드를 실행합니다.
2. 테스트용 빈 문서나 로컬 HTML 입력창에서 한영 키를 여러 차례 눌러 실제 입력과 `한/a` 표시가 일치하는지 확인합니다.
3. 영문 상태에서 Caps Lock을 켰다가 꺼 `A/a`와 실제 입력이 일치하는지 확인합니다. 검증 후 원래 키 상태로 복구합니다.
4. CatchType을 켠 경우, Windows IME가 영문이어도 CatchType 한글 상태에서 `한`이 표시되는지 확인합니다.
5. CatchType을 일시 중지하거나 끈 뒤 Windows IME 판별로 돌아오는지 확인합니다.
6. 모니터 네 모서리와 배율이 다른 모니터 사이를 이동해 표시가 잘리거나 글꼴 크기가 어긋나지 않는지 확인합니다.
7. 별도 작업이 없는 상태에서 Explorer 재시작 후 트레이 아이콘이 복구되고 종료 메뉴가 작동하는지 확인합니다.
