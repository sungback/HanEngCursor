# 상태 소유권과 오류 처리

메인 스레드의 `App`이 메인 창, 오버레이, 트레이, 선택적인 CatchType 모니터를 소유합니다. 가변 전역 상태는 사용하지 않습니다. CatchType 조회 결과도 모니터 인스턴스별로 보관합니다.

창 프로시저는 `GWLP_USERDATA`에 연결된 상태에 접근합니다. 상태의 주소는 `Box`로 고정하며 창을 제거하기 전에 연결을 해제합니다. 오버레이는 창을 먼저 제거한 뒤 그리기 상태와 글꼴을 해제합니다.

트레이 메뉴는 창 핸들만 전달받아 실행하므로 메뉴 내부 메시지 루프가 타이머를 처리해도 트레이 객체를 중복으로 빌리지 않습니다. 타이머 업데이트 자체에도 재진입 방지가 있습니다.

## 오류 처리 기준

- 창 클래스 등록, 창 생성, 상태 연결, 글꼴 생성, 투명도 설정, 트레이 아이콘 리소스 로드, 타이머 생성에 실패하면 초기화를 중단하고 이미 생성한 자원을 정리합니다.
- `GetMessageW`의 오류 반환(-1)과 정상 종료(0)를 구분합니다.
- 실행 중 오버레이 위치·그리기 갱신 요청, 글꼴 크기 변경, 메뉴 생성·명령 전달에 실패하면 메시지 루프를 종료합니다. 자원을 정리한 뒤 오류 대화상자를 표시하고 실패 종료 코드를 반환합니다.
- 트레이 등록·갱신 실패는 일시적인 Shell 오류로 취급합니다. 앱과 오버레이를 유지하면서 1초 간격으로 복구를 재시도합니다. 갱신 실패 시 재등록을, 중복 등록 시 갱신을 시도합니다. `TaskbarCreated`를 받으면 등록 상태를 초기화하고 다음 50ms 타이머에 복구합니다. 메시지가 누락되어도 5초 간격의 점검으로 재등록을 시도합니다.
- 메뉴 취소는 정상 동작입니다. 커서 위치나 모니터 정보를 일시적으로 조회하지 못하면 이전 표시를 유지하고 다음 타이머에 다시 시도합니다.
- CatchType은 선택적인 연동입니다. 시작하거나 조회하지 못하면 Windows IME 판별로 돌아갑니다.
- 타이머·창·메뉴·GDI 자원 해제와 트레이 제거는 종료 시 최선의 노력으로 수행하며 추가 대화상자를 표시하지 않습니다.
- 트레이 아이콘은 `LR_SHARED`로 로드하므로 Windows가 소유합니다. 직접 `DestroyIcon`으로 제거하지 않습니다.
- 필수 아이콘 리소스 컴파일이 실패하면 빌드도 실패합니다.

모니터 배율은 DPI 매니페스트와 `GetDpiForWindow`로 처리합니다. 표시·글꼴·간격을 함께 조정하고, 창이 새 모니터로 이동하면서 DPI가 바뀌면 같은 타이머 안에서 다시 배치합니다. 경계 계산은 현재 커서 모니터의 작업 영역을 기준으로 합니다. 실제 검증 범위는 [검증 기록](validation.md)을 참조하세요.
